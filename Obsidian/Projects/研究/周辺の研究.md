# 0. 先に用語整理

## progression

**progression** は、日本語だとだいたい **系統進行**、**連続青通過**、**信号協調による流れのよさ** くらいの意味です。

たとえば、ある幹線道路に信号が3つ並んでいるとします。1つ目の信号を青で出発した車群が、2つ目、3つ目にも青で到着できれば、車は止まらずに進めます。このように、複数信号をうまくつないで車群を流すことを **progression** と呼びます。

もう少し専門的に言うと、

**信号間のオフセットを調整して、上流交差点を出た車群が下流交差点の青時間に到着しやすくすること**

です。

これはあなたの研究でいう **系統効果** とかなり近い。ただし、progression は実務・green wave 系の文脈でよく使われる言葉で、**「車群が青帯に乗って進む」** という現象寄りの言葉です。一方、あなたが使っている coordination efficiency / 系統効果は、**オフセットを変えたときに遅れがどれだけ変わるか**という感度の概念です。榊原・大口の論文でも、coordination efficiency は「offset が delay にどれだけ効くか」という意味で整理されています。

---

## green wave

**green wave** は、progression がうまく実現した状態のことです。

道路を一定速度で走ると、次々と青信号に当たる。  
これを「青信号の波に乗る」という意味で **green wave** と言います。

ただし、green wave はやや実務的・直感的な言葉で、論文では **bandwidth** や **progression** のほうがよく出ます。

---

## bandwidth

**bandwidth** は、green wave が成立する「時間の幅」です。

たとえば、ある信号を出発する車が、10秒間の範囲で出発すれば、その後の信号を全部青で通れるとします。この10秒が **bandwidth** です。

つまり、

**止まらずに連続通過できる出発時刻の許容幅**

です。

MAXBAND や MULTIBAND は、この bandwidth を大きくすることを目的にした信号制御手法です。榊原・大口のレビューでも、MAXBAND は「隣接交差点間を停止せずに走れる時間帯を最大化する方法」として整理されています。

---

## cycle length

**cycle length** は、信号が一周する時間です。

たとえば、主道路青 → 黄 → 赤 → 交差道路青 → 黄 → 赤 → また主道路青、という1サイクルが120秒なら、

[  
C = 120\ \mathrm{s}  
]

です。

FHWA の信号制御解説では、coordination mode において重要なパラメータとして **cycle length, offset, split** の3つが挙げられています。([FHWA Operations](https://ops.fhwa.dot.gov/publications/signal_timing/05.htm?utm_source=chatgpt.com "SIGNAL TIMING ON A SHOESTRING - V. Coordination Timing Issues"))

---

## offset

**offset** は、2つの信号の青開始時刻のズレです。

上流信号の青開始から、下流信号の青開始が何秒遅れるか。  
あるいは、サイクル長で割って比率で表すこともあります。

あなたの研究でいう

[  
x  
]

です。

---

## split

**split** は、1サイクルのうち、ある方向に青を与える割合です。

たとえばサイクル長120秒で、主方向の青が72秒なら、

[  
g = 72/120 = 0.6  
]

です。

あなたの研究でいう (g_i) や (M(i)) に近いです。

---

## resonance / resonant cycle

**resonance** は、物理でいう「共振」に近い言葉です。

ブランコを考えるとわかりやすいです。ブランコは、ちょうどよいタイミングで押すと大きく揺れます。タイミングが合わないと、あまり揺れません。

交通信号の **resonant cycle** も似ています。

**交差点間隔 (L)、走行速度 (V)、サイクル長 (C) のタイミングがうまく噛み合って、車群が青に乗りやすくなるサイクル長**

のことです。

FHWA は resonant cycle length を、regular linear / grid networks において、他の cycle length よりかなり良い運用を与える cycle length と説明しています。また、その発生理由は、交差点間隔とサイクル長が progression と相性を持つためだと説明しています。([FHWA Operations](https://ops.fhwa.dot.gov/publications/signal_timing/05.htm?utm_source=chatgpt.com "SIGNAL TIMING ON A SHOESTRING - V. Coordination Timing Issues"))

Shelby, Bullock, Gettman の論文では、resonant cycle は **幅広い交通量条件で良好な arterial progression を与える cycle length** と説明されています。([Sage Journals](https://journals.sagepub.com/doi/10.1177/0361198105192500122?utm_source=chatgpt.com "Resonant Cycles in Traffic Signal Control - Steven G. Shelby, Darcy M. Bullock, Douglas Gettman, 2005"))

あなたの研究の言葉で言えば、

[  
\Lambda = \frac{L}{CV}  
]

が hce に近づくような (C,V,L) の組み合わせは、resonant cycle 的な性質を持っている、と言えます。

---

## arterial

**arterial** は幹線道路です。

住宅街の細街路ではなく、信号が連続して並び、比較的多くの交通を処理する道路です。  
あなたの研究でいう「信号制御された路線」「幹線路線」に近いです。

---

## speed offset coordination

Yuan & Ioannou の文脈で出てくる **speed offset coordination** は、少し特殊です。

普通の信号協調は、

**信号側の offset を調整して、車群が青に合うようにする**

という発想です。

一方、speed offset coordination は、

**信号の offset だけでなく、車両側の推奨速度も調整して、青に合うようにする**

という発想です。

つまり、

[  
\text{信号を合わせる}  
]

だけでなく、

[  
\text{車の速度も合わせる}  
]

ということです。

Yuan & Ioannou では、DSO agent が隣接交差点間の relative offset と上下方向の recommended speed を計算します。([arXiv](https://arxiv.org/abs/2404.06382?utm_source=chatgpt.com "Traffic Signal Control and Speed Offset Coordination Using Q-Learning for Arterial Road Networks"))

# 2. MAXBAND / MULTIBAND / green wave 系

## 2.1 MAXBAND とは

**MAXBAND** は、かなり古典的で重要な方法です。

目的は、

**幹線道路上で車が止まらずに通過できる green bandwidth を最大化すること**

です。

簡単に言うと、

「この時間帯に出発した車は、なるべく全部の信号を青で通れる」

という時間幅を最大にするモデルです。

MAXBAND は、cycle time を範囲内で選び、design speed も許容範囲内で変化させ、offset などを決めるモデルとして知られています。([TRID](https://trid.trb.org/View/776057?utm_source=chatgpt.com "Resonant Cycles in Traffic Signal Control - TRID"))

榊原・大口のレビューでも、MAXBAND は green wave / time bandwidth 最大化系の代表として整理されており、RHODES では cycle time を上下限内で選び、速度の組み合わせや green split を計算して、車両が通過可能な時間幅を最大化すると説明されています。

---

## 2.2 MULTIBAND とは

**MULTIBAND** は、MAXBAND の発展形です。

MAXBAND は比較的「一本の同じ帯」を作る発想が強いのに対して、MULTIBAND はリンクごと、方向ごとに違う bandwidth を扱えるようにしたものです。

つまり、

**全部のリンクに同じ green wave を押し付けるのではなく、リンクごとの条件に応じた progression を作る**

という方向です。

これはあなたの「各リンク・各区間の系統効果が複雑に絡む」という感覚にかなり近いです。

---

## 2.3 あなたの研究との違い

MAXBAND / MULTIBAND は、

**止まらずに通過できる時間幅を最大化する**

研究です。

あなたの研究は、

**最適オフセットを与えたとき、どれだけ遅れを小さくできる構造かを診断する**

研究です。

似ていますが、目的関数が違います。

- MAXBAND 系：green bandwidth を最大化する
    
- あなた：delay reduction potential を評価する
    

さらに、あなたは ( \Lambda=L/(CV) ) と hce/lce を使って、

**なぜその (C,V,L) で遅れが小さくなりやすいのか**

を説明したい。

ここが貢献になり得ます。

# 3. 動的制御・AI制御系

ここからは、Yuan & Ioannou のように、

**信号の cycle length や split、offset、車両の推奨速度を動的に変える**

研究です。

---

## 3.1 動的制御とは

**動的制御** は、時間帯や交通状態に応じて制御パラメータを変えることです。

固定制御では、

「朝ピーク用の信号設定」  
「昼間用の信号設定」  
「夜間用の信号設定」

のようにあらかじめ設定しておきます。

動的制御では、交通量・キュー・信号状態を見ながら、

[  
C,\ split,\ offset,\ speed  
]

をその場で変えます。

---

## 3.2 RL / Q-learning とは

**RL** は reinforcement learning、つまり強化学習です。

強化学習は、

- ある状態 (s) を見る
    
- 行動 (a) を選ぶ
    
- 結果として報酬 (r) を得る
    
- 長期的に報酬が大きくなるように行動の選び方を学習する
    

という枠組みです。

交通信号なら、

- 状態：キュー長、交通量、信号状態
    
- 行動：青時間を伸ばす、サイクル長を変える、offset を変える
    
- 報酬：遅れが小さい、停止回数が少ない、キューが短い
    

という形になります。

**Q-learning** は、強化学習の代表的な手法です。  
ある状態である行動を取ると将来どれくらい良いか、という (Q(s,a)) を学習します。

---

## 3.3 Yuan & Ioannou, 2024

Yuan & Ioannou の論文は、かなりあなたの関心に近いです。

タイトルは、

**Traffic Signal Control and Speed Offset Coordination Using Q-Learning for Arterial Road Networks**

です。

彼らは、幹線道路と高速道路ランプが接続するネットワークで、arterial traffic signal control と dynamic speed offset coordination を Q-learning で統合しています。([arXiv](https://arxiv.org/abs/2404.06382?utm_source=chatgpt.com "Traffic Signal Control and Speed Offset Coordination Using Q-Learning for Arterial Road Networks"))

この研究では2種類の agent が出てきます。

### TSC agent

**TSC** は Traffic Signal Control です。

TSC agent は、

- cycle length
    
- split
    

を決めます。

つまり、信号側の制御です。

### DSO agent

**DSO** は Dynamic Speed Offset coordination です。

DSO agent は、

- relative offset
    
- 上り方向の recommended speed
    
- 下り方向の recommended speed
    

を決めます。

つまり、信号の offset と車両の推奨速度を一緒に調整します。

Yuan & Ioannou の要旨では、TSC agent は交差点需要や高速道路オフランプのキューをもとに cycle length と split を計算し、DSO agent は隣接交差点間の物理距離、キュー、信号サイクルをもとに relative offset と双方向の recommended speed を計算すると説明されています。([arXiv](https://arxiv.org/abs/2404.06382?utm_source=chatgpt.com "Traffic Signal Control and Speed Offset Coordination Using Q-Learning for Arterial Road Networks"))

# 5. GLOSA / speed guidance 系

## 5.1 GLOSA とは

**GLOSA** は Green Light Optimal Speed Advisory の略です。

これは、

**次の信号を青で通るために、車に推奨速度を教えるシステム**

です。

たとえば、今の速度だと赤で止まる。でも少しゆっくり走れば、信号が青になるタイミングで到着できる。  
このとき、「少し速度を落として走れ」と車に教えるのが GLOSA です。

榊原・大口のレビューでも、車両位置・速度情報が実用化され、赤信号停止を避けるために速度を調整する speed guidance / eco-driving 研究が必要になっており、GLOSA がその例として挙げられています。

---

GLOSA は、基本的に

**個別車両にどの速度で走るべきかを教える**

研究です。

あなたの研究は、

**路線全体として、どの (C,V,L) 条件なら信号制御が効きやすいかを評価する**

研究です。

つまり、GLOSA は車両側の制御。  
あなたは道路・信号・運行速度側の設計診断。

と整理すれば差別化できます。

## 示唆2：Yuan & Ioannou は「近いAI研究」として入れるべき

Yuan & Ioannou は、cycle length, split, offset, recommended speed を Q-learning で動かしているので、あなたの関心にかなり近いです。

**彼らは制御政策の学習。あなたは制御が効きやすい構造条件の診断。**

ここを明確にする。

## 示唆3：あなたの研究は「最適化」ではなく「診断」

これは一番大事です。

既存研究には、

- bandwidth を最大化する
    
- AIで control policy を学習する
    

がたくさんあります。

あなたはそこに正面から突っ込むより、

**最適化を始める前に、その (C,V,L) 条件が信号制御に向いているかを診断する**

という立場にした方が強いです。

# 11. 最終的な位置づけ

かなり短く言うなら、こうです。

**resonant cycle 研究は、交差点間隔・速度・サイクル長が噛み合うと progression が良くなることを示している。Yuan & Ioannou のような AI 制御研究は、cycle length, split, offset, recommended speed を動的に操作して性能を改善しようとしている。これに対して本研究は、(\Lambda=L/(CV)) と hce/lce 条件を用いて、そもそもどの (C,V,L) 条件なら信号制御による遅れ低減が期待できるかを診断する。**

これでかなり読みやすくなると思います。
